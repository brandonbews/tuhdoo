## Context

Dogfooding capture from Brandon (2026-08-01). The generated markdown files on the `tuhdoo` data branch (backlog.md and friends, produced by internal/views) are the human-readable face of the ledger. Right now they're utilitarian dumps; they should be pretty, or at least easy to read and scan at a glance.

**Design target (Brandon decided 2026-07-31): optimize for rendered markdown on a git host** — someone browsing the tuhdoo branch on GitHub. Raw-terminal legibility is best-effort only; terminal readers are already served by `tuhdoo backlog` and the TUI. Tables, badges, and other rendered-first constructs are on the table.

## The ask

A design pass on the generated markdown:

- Decide the reading experience first (what does someone glancing at the branch on GitHub want to see, in what order?), then shape the views to serve it: clear headings, tables where they scan better than lists, sensible ordering (actionable states before done/archived), short IDs, restrained use of bold/badges. Taste over decoration.
- Keep every view deterministic and generated by pure functions (T1) — same events in, same bytes out.

## Acceptance

- Views read as designed on GitHub's rendered view; raw text remains parseable but is not the design driver.
- View generation stays pure and table-driven-testable; golden tests updated to the new output; make test lint green.
- Before/after of backlog.md (as rendered — screenshots or links in the PR) so the design change is reviewable as behavior.
